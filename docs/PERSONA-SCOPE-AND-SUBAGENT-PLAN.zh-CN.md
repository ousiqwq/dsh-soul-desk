# Soul Desk 三层人设规则与原生子代理适配规划

日期：2026-11-12。状态：已在 0.4.0 实现；验收范围与边界见 [0.4.0 验收记录](./RELEASE-0.4.0.zh-CN.md)。以下保留实施依据与规则说明。

用户已确认采用 **全局默认 → 工作区默认 → 会话选择** 三层规则，截图中的会话人设下拉优先。原生子代理默认不复用父人设，可选复用父人设或指定另一人设。

## 1. 已核对的实际情况

- 正式 DSH 为 `0.2.2-rc.2`。当前安装 Soul Desk `0.3.0`，公开文档版本已到 `0.3.2`；`index.js`、`store.js`、`persona-scope.js`、`client.js` 四个核心文件的字节内容一致。
- 数据结构为 v2，实际已有会话绑定。`SoulStore.action('session-select')` 会保存指定人设及 `none`；选择“跟随默认”则删除该会话记录。因此已有保存功能，缺少的是完整规则结构和每个会话的明确状态。
- `persona-scope.js` 使用 `scopeChainOf()` 向父级找人设；`SoulStore.resolve()` 最后回到全局默认。因此当前子代理会自动继承父人设，也可能得到全局人设。已有原生作用域测试明确覆盖了这一行为，本次定向运行通过。
- `runtime.forPrompt()` 绑定本轮人设，记忆工具使用 `forExecution()` 获取归属。现有“已发送请求不跟随下一次人设切换”的设计应保留。
- `SoulStore.view()` 和前端菜单只考虑直接会话绑定及全局默认；新增工作区与派生规则后必须使用同一个服务端解析结果，否则菜单显示与实际注入会不一致。
- 删除人设会删掉关联会话绑定，可能使原会话自动使用另一默认人设。新规则应避免这种无提示切换。
- Team Desk 的 `PersonaBinding.tsx` 也调用现有 Soul API。它是第二个操作入口，必须同步展示实际生效来源，不另存一份绑定。
- 新版原生 `subagents` 有具名/多层子代理、`spawn`、`fork`、生命周期事件及冷恢复。`subagent/start` 提供直接父会话 ID，局部 Agent 已可查询；普通会话 fork 与原生子代理属于不同关系。

依据：`persona-scope.js`、`store.js`、`client.js`、`memory-tools.js`、`tests/persona-scope.test.mjs`；当前宿主的 `dsh-subagent`、`dsh-subagent-spawn-in-process`、`dsh-subagent-fork-in-process` 与工作区控制器；相邻 Team Desk 的 `src/client/PersonaBinding.tsx`。

## 2. 普通会话的三层规则

插件总开关关闭时停止 Soul 人格与个人记忆功能。总开关启用后，按下表由上至下解析：

| 优先级 | 位置 | 可选值 |
| --- | --- | --- |
| 1 | 当前会话，包含截图下拉和设置页中的同一会话 | 跟随默认 / 指定人设 / 此会话不使用 |
| 2 | 所属工作区 | 继承全局 / 指定人设 / 此工作区不使用 |
| 3 | 全局默认 | 指定人设 / 不使用默认人设 |

明确选择“不使用”即结束解析，不能再回退到上层。只有“跟随/继承”才继续查找。修改全局或工作区默认，只影响选择跟随的会话，不覆盖明确指定或停用的会话。

工作区优先使用宿主的稳定 workspace ID，显示名只用于界面。工作区改名不丢规则；移动会话后，明确选择保留，跟随默认的会话从下一次请求开始采用目标工作区规则。不能用工具参数里的 cwd 判断人设归属。

截图中的下拉保留现有位置和直接操作方式，显示“当前人设/不使用”并提供来源提示，例如“跟随工作区：逆向 → 人设 A”。设置页修改同一会话时写入同一条记录，不设置第二个互相覆盖的开关。

## 3. 原生子代理的人设规则

新增“派出子代理时的人设”设置，与主会话当前使用的人设分开：

| 模式 | 行为 |
| --- | --- |
| **不使用 Soul 人设（默认）** | 不注入本插件的人格、个人记忆和记忆指令；本插件记忆工具也不能访问或写入任何人设 |
| 复用派出者当前人设 | 采用直接派出者在本轮请求实际使用的人设；派出者无 Soul 人设时，子代理也无，不回退到全局 |
| 使用指定人设 | 采用用户指定的人设及其记忆，与派出者当前人设相互独立 |

这只管理 Soul Desk 的人设，不清除 DSH 原生 Agent preset、任务指令或团队协作规则。

子代理默认策略可在全局、工作区、会话设置。全局初始为“不使用”；工作区及根会话可覆盖。一个原生树内未另行设置的后代沿用这条派生策略，但“复用当前人设”始终指其直接派出者，不强行取根代理。子会话若有明确的自身选择，该选择优先。

创建时捕获派生决策，记录来源和选中的人设 ID。父会话之后切换人设或调整派生默认，不批量改写已创建子会话；用户仍能单独修改子会话。并发创建也必须在第一个模型请求之前应用正确规则，不能先注入父人设再异步纠正。

需要结合原生生命周期、作用域与持久身份实现，并在提示词/工具统一解析处兜底。不可只靠浏览器菜单、易失 WeakMap 或模型遵守“不继承”文字说明。异步登记与首次提示词装配之间必须有明确的等待顺序，保存失败时停止该次 Soul 注入并提示，不悄悄继承。

### 三类关系分别处理

- **Team Desk 外层独立成员**：属于独立根会话，各自按三层规则选择；不因属于同一团队就套子代理策略。
- **DSH 原生 spawn / fork 子代理及多层后代**：采用上述派生规则，并记录自己的 session ID、直接父 ID 及创建来源。
- **普通会话复制/fork、原生恢复、外部 ACP 后端**：按宿主的真实关系分类。冷恢复使用已存绑定，不因新 Agent 对象产生而重新继承。ACP 等无法由本插件控制提示词/工具的后端显示为“不支持控制/未验证”，不能宣称已应用固定人设。

**fork 的边界**：原生 fork 会继承父会话已完成轮次的历史。关闭 Soul 的后续注入不会抹除原历史里已经存在的人设表达或个人信息；若要求不带父历史，应使用原生 fresh spawn。插件不自动改写用户选择的原生 fork 行为。

## 4. 设置界面与逐会话记录

“私人灵魂”设置中保留人设编辑、记忆、导入导出，增加“使用规则”区域，布局接近 Capability Desk：

1. 范围选择：全局默认、各工作区、会话列表。
2. 全局/工作区分别设置默认人设与子代理派生规则。
3. 会话列表显示标题、所属工作区、普通/子代理关系、选择、实际人设和来源，可搜索筛选。
4. 当前会话可设置自身人设和派生策略。截图下拉仍是最快操作入口，与列表实时同步。
5. 子代理只读聊天视图也应能看到规则来源；是否能修改按原生 UI 权限处理。验证 `conversation.input.dock` 与 `conversation.session.header.actions` 的挂载条件，避免无输入框的子代理页面丢失菜单或重复显示。

每个会话明确保存选择状态 `follow / persona / none`。子代理额外保存创建时的派生决策与来源。父子关系等事实以宿主为权威，本插件只保存解析所需引用和可恢复的决策，不重新维护一套团队名册。

“选择跟随”与“缺少记录”不能混为一谈。迁移时识别现有会话并补足跟随状态；新会话在原生创建/首次使用边界登记，读取 GET 接口不偷偷改写数据。尚未完成归属识别的旧会话保留原记录并显示待识别，不根据标题、名称或不存在的父 Agent 猜归属。

多标签、Team Desk 多窗格、切换会话、刷新和服务重启均从同一份服务端状态恢复；写入成功前不把临时 UI 选择当成已保存。保留修订冲突检查和原子写入，冲突后刷新对应状态，不覆盖其他会话的新选择。

## 5. 数据升级与异常处理

建议在功能版本 `0.4.0` 引入 schema v3，包含全局/工作区默认、会话选择、子代理默认和派生来源。沿用原 `library.json`、原子持久化与备份方式，不增加另一个人设数据库。

- 迁移前保存 v2 原始备份；保留全部人设、记忆和既有明确会话绑定。
- v2 指定 ID 转为 `persona`，`none` 转为停用；普通根会话未设定的转为跟随。没有明确绑定的原生子代理按新的默认“不使用”处理，不能把旧的隐式继承迁移成用户明确选择。
- 迁移只在受控更新/启动边界进行，避免运行中的旧请求突然换归属。迁移失败保留原文件，不生成半套新状态。
- 指定人设被删除、无效或内容为空时，该规则保持“已失效”的来源记录并暂停 Soul 注入，提示用户重新选择；不能自动换到另一人设。重命名因 ID 不变而继续有效。
- 调整导出/导入版本；旧 v2 备份可明确迁移，merge 时重映射全部新规则内的人设 ID。旧插件拒绝 v3，回滚需成套恢复旧数据及旧插件。
- 同一轮提示词与记忆工具共用已绑定人设，不因菜单切换把正在写的记忆归到另一个人设；总开关停用仍作为即时停止入口。服务重启后不能用旧内存映射代替持久状态。

## 6. 实施范围和顺序

| 阶段 | 修改范围 | 完成条件 |
| --- | --- | --- |
| 1. 规则与迁移 | `store.js`、独立解析逻辑、v2→v3 迁移 | 所有选择及来源可序列化；旧绑定无损；不存在隐式切换 |
| 2. 原生作用域接入 | `persona-scope.js`、`index.js`、`prompt-policy.js`、`memory-tools.js` | 主会话及多层 spawn/fork 的首轮、续轮、恢复均正确；默认子代理无 Soul 人设/记忆权限 |
| 3. API 与界面 | `http-api.js`、`client.js`、locale、Team Desk 的人设绑定适配 | 下拉与设置表共用真实解析结果；多会话、多窗格和工作区切换不串状态 |
| 4. 验收与发布 | 定向测试、浏览器、原生运行记录、中英文文档 | 通过下列验收后再部署和发布；安装说明继续放在介绍后 |

优先使用 DSH 已公开的 subagent、scope、workspace 与 session API，不先修改宿主内核。实施前做最小宿主集成验证，确认派生决策捕获和首次提示词装配的顺序；若公开接口确有缺口，再明确缺口及最小适配范围。

现有 `/private-soul/v2` 调用存在 Team Desk 消费者，不能随数据 schema 升级直接移除。规划保留兼容请求及标量 `override`，扩展 `selection`、`effectivePersonaId`、`source` 和关系信息；新版前端统一使用扩展字段。旧的 `session-select` 空值请求转为明确保存 `follow`，不再删除记录。Team Desk 的“跟随全局”文案与来源显示需要同步修正。

## 7. 验收场景

- 全局 A、工作区 B、会话 C：该会话用 C；切换跟随后用 B；明确不使用始终无 Soul 人设。改全局/工作区不覆盖 C 或 none。
- 同工作区两个会话分别使用 A 与 B，刷新、跨标签及服务重启后保持；工作区改名、会话移动后来源正确。
- 父会话用 A，子代理策略未设置：fresh spawn、fork 和嵌套后代都不新增 Soul 人设及私有记忆注入；记忆工具实际拒绝访问。
- 选择复用：子代理使用派出者本轮实际人设。父本轮仍为 A、界面刚切 B 时，正在派出的子代理不能偷换为 B。
- 选择固定 C：各子代理使用 C；一个子代理手动改为 B 后，其后续请求保持 B，不能被父级批量改回。
- 父无 Soul 人设且设置复用：子代理也无，不回退全局。失效/删除的人设不导致其他人格自动接管。
- 多层父子、并发创建、首次请求、续轮、冷恢复与普通会话 fork 分别验证；原生任务树和 Team Desk 外层成员不混淆。
- 旧 v2 档案、明确 none、跟随、导入 merge/replace、冲突写入、失败回滚、卸载重装均保留正确归属。
- 不使用人设时不发送人格/私人记忆，但保留原生任务、工具 schema、协作与权限；使用时继续验证 priority/complete/append 三种模式。
- 中英文、实时切换、深浅主题、窄屏、无输入框子代理视图与 Team Desk 多窗格都显示实际生效值。先用隔离存档和脚本化模型验收，再进行明确范围的真实模型验证。
