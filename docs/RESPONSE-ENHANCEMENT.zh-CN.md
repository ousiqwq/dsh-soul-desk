# 提示词增强本地验收

历史验收版本：0.5.0-local.1；验证宿主：DSH 0.2.2-rc.2。此记录随 GitHub 源码同步。当前版本 `0.5.0` 已迁入上游提示词原文并发布到 npm，见文末说明。

- 默认关闭的独立全局开关，右侧为原生高级设置窗口。
- 三项额外要求（简洁开场、完整交付、保留命名）默认关闭，开启后追加在原文之后，不改动原文；是否应用于子代理可单独设置。可以编辑、预览、保存新增提示词。保存不会开启开关，恢复默认只改草稿。
- 原有人设、个人记忆段落从不被改写。上游正文把作用范围限定在内容层面，并声明不改变工具目录、调用协议、Plan 规则、审批、沙箱和结构化输出报告——这些机制仍由宿主决定。
- 配置与 library.json 分开持久化，支持修订号冲突保护和十份滚动备份。损坏时仅关闭增强，保留原文件。

隔离实例使用合成模型和合成数据；以上验证组装、持久化和工具执行契约，不保证所有外部模型每次都遵循文风提示。配置和固定保护说明为提示词指导，运行权限仍由 DSH 原生机制负责。

## 真实模型补测

使用当前 DSH 配置的 `example-provider / example-model` 端点，进行了四次无工具、无生产会话的独立请求。测试使用已安装版本的提示词生成器及合成人设、记忆，没有加载用户真实的人设内容。

- 基线：人设前缀与合成记忆正常，不出现新增测试标记。
- 自定义增强：加入的测试后缀实际出现在回答中，同时保留原有人设前缀与记忆答案。
- 默认增强：算术样例给出简洁结果并保留人设称呼。
- 默认增强：PowerShell 脚本样例保留给定路径、名称和值，包含 JSON 转换和文件写入，未谎称已实际执行。

四例均通过。原 library.json 和生产增强开关、修订号均未改变。完整合成输入、输出及检查结果保存在本机忽略目录 `operations/enhancement-20261115/real-model-check.json`。

这属于小样本行为验证，不是统计效果对比。基线本身也能完成一般任务，不能由此推导出增强的普遍提升幅度。这些补测在提示词原文迁入之前执行，因此没有验证上游原文的实际效果。

## 提示词原文（0.5.0）

`upstream-prompt.js` 按字节保存上游提示词：执行模式正文 10246 字符，人设指针 170 字符，Plan 追加 349 字符，PTC 追加 400 字符，结构化输出追加 138 字符，另有四个结构锚点。默认设置下 `renderEnhancementPrompt()` 直接返回正文，不加包装标题、摘要或额外边界句；`tests/upstream-prompt.test.mjs` 用随包内置的 `vendor/dsh-unrestricted/rules-0.2.9.js` 逐字节比对，并校验每个 `sha256`。

框架层面仍是适配集成：上游把追加文本挂在人设旁的既有段落，我们插入独立的 `private-soul:response-enhancement` 段，便于独立编辑、预览和关闭。注入内容相同，段落名与插入位置不同。源码一致不等于行为等价的实证，实际遵循程度取决于所用模型。
